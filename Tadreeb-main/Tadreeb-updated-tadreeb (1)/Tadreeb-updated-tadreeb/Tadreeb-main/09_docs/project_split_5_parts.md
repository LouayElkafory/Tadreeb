# تقسيم المشروع على 5 أقسام (لتوزيعه على الفريق)
## RAG Chatbot لبرامج وزارة الاتصالات (ITI / NTI / رواد مصر الرقمية) — نسخة Ollama

> التقسيم مبني على تسلسل الـpipeline نفسه، بحيث كل قسم يعتمد على مخرجات اللي قبله، لكن في نفس الوقت ممكن يشتغل جزء كبير منهم بالتوازي بعد أول أسبوع (لما يبقى فيه عينة بيانات جاهزة للتجربة).

---

## القسم 1: جمع البيانات (Data Collection / Scraping)

**المسؤولية:** كل حاجة قبل التنظيف — جلب البيانات الخام من المصادر الرسمية والمجتمعية.

**المهام:**
- Scraping المواقع الرسمية الثلاثة (ITI، NTI، DEPI) — نصوص + هيكلة الصفحات.
- استخراج ملفات PDF ودمج محتواها.
- جمع منشورات/تعليقات الصفحات الرسمية على فيسبوك (بيانات المجتمع).
- تسجيل الـmetadata الأساسية مع كل مصدر (`source_url`, `program_name`, `date_scraped`).

**الفولدرات/الملفات المسؤول عنها:**
```
scraping/
data/raw/
```

**المخرج النهائي:** فولدر `data/raw/` ممتلئ ومنظم لكل برنامج (official + community).

**أدوات مقترحة:** `requests`, `BeautifulSoup`, `Selenium`/`Playwright` (لو المحتوى Dynamic), `PyMuPDF`/`pdfplumber`.

---

## القسم 2: التنظيف والتقسيم (Preprocessing & Chunking)

**المسؤولية:** تحويل البيانات الخام لصيغة نظيفة ومقسّمة جاهزة للـEmbedding.

**المهام:**
- تنظيف النص (إزالة boilerplate، تطبيع عربي، إزالة تكرار).
- الفصل بين Official Info وCommunity Info بوضوح في الـmetadata.
- تقسيم النص لـChunks بطريقة semantic (سؤال+إجابة أو فقرة كاملة) مع الحفاظ على الـmetadata.
- التعامل الخاص مع الجداول (زي جدول الـ31 مسار في DEPI) كـstructured data.

**الفولدرات/الملفات المسؤول عنها:**
```
preprocessing/
data/processed/
data/chunks/
docs/data_dictionary.md
```

**المخرج النهائي:** ملفات `*_chunks.jsonl` جاهزة لكل برنامج بالـmetadata schema الموحد.

**أدوات مقترحة:** `re`, `pyarabic` (تطبيع عربي), `langchain.text_splitter` أو تقسيم يدوي.

---

## القسم 3: الـEmbeddings + Vector Database (تحت مظلة Ollama)

**المسؤولية:** تحويل الـChunks لمتجهات وتخزينها، واختيار وتجربة النماذج المحلية.

**المهام:**
- تثبيت وتشغيل Ollama + تحميل نماذج الـembedding (`nomic-embed-text` أو بديل).
- عمل `model_benchmark.py` لمقارنة أكتر من نموذج embedding على عينة من الأسئلة الحقيقية.
- بناء وتغذية الـVector DB (ChromaDB أو Qdrant، محلي بالكامل).
- التأكد إن كل vector محمّل بالـmetadata بتاعته صح (program_name, info_type... إلخ).

**الفولدرات/الملفات المسؤول عنها:**
```
embeddings/
docs/ollama_setup_guide.md
```

**المخرج النهائي:** Vector DB جاهزة ومفهرسة بكل الـchunks، مع تقرير مقارنة نماذج الـembedding.

**أدوات مقترحة:** مكتبة `ollama` بايثون، `chromadb`, `sentence-transformers` (كبديل/مقارنة).

---

## القسم 4: الـRetrieval + الـGeneration (قلب الـRAG)

**المسؤولية:** الربط بين البحث عن المعلومة الصح وتوليد إجابة منها عن طريق نموذج Ollama.

**المهام:**
- بناء منطق الاسترجاع (similarity search + فلترة metadata حسب البرنامج المذكور في السؤال).
- (اختياري لكن موصى بيه) إضافة إعادة ترتيب (Reranking).
- كتابة الـPrompt Templates اللي تجبر النموذج يجاوب من الـcontext بس، ويقول صراحة لو المعلومة مش متوفرة، ويفضّل المصدر الرسمي عند التعارض.
- عمل `model_comparison_results.md` لمقارنة نماذج الـgeneration (Qwen, Aya, Llama) على أسئلة حقيقية واختيار الأنسب للعربي المصري.
- الاتصال الفعلي بـ`ollama.chat()` وتوليد الإجابة النهائية مع الـcitation (رابط المصدر).

**الفولدرات/الملفات المسؤول عنها:**
```
retrieval/
generation/
```

**المخرج النهائي:** دالة/سكربت بياخد سؤال المستخدم ويرجع إجابة مبنية على المصادر + رابط المصدر.

**أدوات مقترحة:** `ollama` بايثون SDK، `chromadb` query API، نماذج reranking صغيرة (`bge-reranker`) لو الوقت سمح.

---

## القسم 5: الواجهة + التقييم + التوثيق (Integration, Evaluation & Docs)

**المسؤولية:** ربط كل الأقسام مع بعض في تطبيق شغال، اختباره، وتوثيق المشروع بالكامل.

**المهام:**
- بناء واجهة بسيطة (Streamlit/Gradio) أو API (FastAPI) تستقبل سؤال المستخدم وتعرض الإجابة.
- بناء مجموعة أسئلة اختبار حقيقية (`test_questions.jsonl`) من نفس الأسئلة اللي جُمعت سابقًا.
- قياس دقة الاسترجاع (Retrieval accuracy) وجودة الإجابة (Faithfulness / Hallucination rate).
- تسجيل الأسئلة اللي البوت فشل يجاوب عليها كويس (`logs/unanswered_questions.log`) كمصدر لتحسين الـKnowledge Base لاحقًا.
- كتابة التوثيق النهائي: README، رسم الـarchitecture diagram، خطوات التشغيل لأي حد جديد في الفريق.

**الفولدرات/الملفات المسؤول عنها:**
```
app/
evaluation/
logs/
docs/ (باقي الملفات + architecture_diagram.png)
README.md
```

**المخرج النهائي:** Chatbot شغال end-to-end + تقرير تقييم + توثيق كامل للمشروع.

**أدوات مقترحة:** `streamlit` أو `gradio`, `fastapi` (لو محتاجين API), أدوات تقييم بسيطة مبنية يدويًا أو `ragas` (لو متاحة offline).

## جدول تسلسل الاعتماديات (Dependencies)

| القسم | بيعتمد على مخرجات | ملاحظة |
|---|---|---|
| 1. جمع البيانات | لا شيء (نقطة البداية) | يقدر يشتغل فورًا |
| 2. التنظيف والتقسيم | القسم 1 | ممكن يبدأ بعينة صغيرة من القسم 1 وهو لسه شغال |
| 3. Embeddings + Vector DB | القسم 2 | إعداد Ollama نفسه يقدر يبدأ فورًا بالتوازي (مش محتاج بيانات) |
| 4. Retrieval + Generation | القسم 3 | إعداد الـPrompt templates يقدر يبدأ مبكرًا بأمثلة تجريبية |
| 5. الواجهة + التقييم | الأقسام 1-4 (تكامل نهائي) | التوثيق وبناء test set يقدروا يبدأوا من الأسبوع الأول |

**توصية للتنسيق:** خصصوا يوم/اجتماع أسبوعي قصير كل الفريق يعرض فيه تقدمه، لأن الأقسام مترابطة بقوة (خصوصًا لو حد في القسم 1 غيّر شكل الـmetadata، لازم الأقسام 2، 3، 4 كلهم يعرفوا فورًا).
